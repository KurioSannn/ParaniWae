# Product Roadmap and Backlog

The roadmap is capability-based, not a promise of calendar delivery. A team should estimate after repository, partner, and dataset discovery.

## Phase 0 - Discovery and hard gates

- [ ] Audit current code/repository and assets.
- [ ] Audit raw user survey/interview data.
- [ ] Select anchor partner and verify authority/consent.
- [ ] Choose one tradition/style and beginner learning scope.
- [ ] Define 8-12 candidate movements with partner; final set is partner decision.
- [ ] Create cultural content permission register.
- [ ] Write movement validation worksheets and safety constraints.
- [ ] Confirm BUDAYA GO! date eligibility with verifiable evidence; do not assume.

**Exit:** product scope, partner, evidence base, and hard constraints are documented.

## Phase 1 - Design and clickable flow

- [ ] Landing and product explanation.
- [ ] Heritage explorer and detail.
- [ ] Academy and lesson flow.
- [ ] Camera setup and practice UI states.
- [ ] Result/progress UI.
- [ ] Verified partner directory.
- [ ] Accessibility and responsive review.

**Exit:** user-tested prototype and page-level acceptance criteria.

## Phase 2 - Functional web MVP vertical slice

- [ ] Auth and learner profile.
- [ ] One partner tradition profile and approved source metadata.
- [ ] One beginner course and selected movements.
- [ ] Camera permission and lifecycle.
- [ ] Pose tracking on supported browsers.
- [ ] Hand tracking where needed.
- [ ] Landmark quality gate.
- [ ] Rule-based movement phase/feature analysis.
- [ ] Instructor-approved rubric and correction mapping.
- [ ] Result persistence and progress page.
- [ ] Unit/integration/E2E tests.

**Exit:** one complete movement learning loop works with a real camera and approved data.

## Phase 3 - Pilot and validation

- [ ] Instructor agreement and baseline scoring protocol.
- [ ] Test across participant identities and devices.
- [ ] AI-versus-instructor comparison.
- [ ] Beginner usability pilot.
- [ ] Learning effectiveness pilot.
- [ ] Cultural knowledge and confidence measurement.
- [ ] Revise rubrics and content.

**Exit:** documented limitations, validated subset of movements, and pilot report.

## Phase 4 - Community and partner operations

- [ ] Verified directory.
- [ ] Partner profile workflow.
- [ ] Content submission/review process.
- [ ] Consent and permission audit log.
- [ ] Class enquiry flow.
- [ ] Partner reporting.

**Exit:** at least one partner uses the system operationally and public information is maintained.

## Phase 5 - Expansion

- [ ] Add another partner/style after separate validation.
- [ ] Add more movements and course levels.
- [ ] Assess whether temporal ML improves over baseline.
- [ ] Add institutional licensing/premium content only after demand and rights validation.
- [ ] Evaluate local-language subtitles/audio where approved.
